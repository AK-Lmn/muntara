# Tunasan, Poblacion, and Putatan pilot inventory

**Coverage: pilot listings in progress.** Source review date: **2026-10-28**. This inventory contains 72 public-service listings: 48 government offices, eight health centers, and 16 public education sites. It is a reviewed starting inventory, not a claim that every eligible facility has been found or that every facility is currently operating at the published address.

By barangay: Tunasan has 24 listings (17 government, three health, four education); Poblacion has 18 (nine government, two health, seven education); Putatan has 30 (22 government, three health, five education).

The pilot boundary is the physical location of a public-facing government office, government health facility, or government-run school/learning center in **Tunasan, Poblacion, or Putatan**. A service area or a name containing a barangay does not establish physical location. Private facilities and offices in other barangays are excluded. Separate public services can share one building; repeated program rows for one clinic do not create another facility.

## Evidence and unknown facts

[data/pilot-places.json](../../data/pilot-places.json) is the importable inventory. Each non-empty public field carries its own source row containing `fieldKey`, `sourceName`, `sourceUrl`, `sourceType`, and `checkedAt`. Repeated citations are intentional: evidence for a phone number does not silently establish an entrance or opening hours. Date checked means the source was reviewed, not that a volunteer visited the site.

The inventory has 535 field-level source rows: 523 official-source rows and 12 OpenStreetMap location rows. OSM supports coordinates only; it does not establish addresses, services, or operating status. No record is marked field-verified. The importer refuses records whose verification state has advanced beyond `awaiting_review` and uses database defaults for new records; the public UI must derive the official-source label from field sources rather than infer a visit.

Google Maps was not scraped. Its [Maps Platform terms](https://cloud.google.com/maps-platform/terms) prohibit scraping and exporting Maps content for use outside its services. Facility facts come from official directories; map points come from OpenStreetMap.

Fourteen listings have map points: two schools use DepEd project coordinates, and 12 use OpenStreetMap mapped features. OSM pins are not entrance-verified. The other 58 locations remain null. Barangay and senior-citizen satellite office street addresses remain null because city sources do not provide exact sites; these entries need reconciliation to current physical counters before navigation can be offered. All entrance, wheelchair, and parking details remain unknown. Service hours are shown only for offices with a published schedule. Contacts are published office contacts; no employee names are stored. Phone formatting is preserved from the source, including the City Health Office's unusual published formatting.

The current Schools Division Office directory now supplies updated addresses and published contacts for schools in the pilot. Older masterlist and allocation-list evidence remains attached where it established prior details. DepEd's PPP coordinates are **project coordinates, not a site visit**, and the citation says so. Confirm entrances and current addresses with each school before claiming navigation accuracy.

The controller's official-source research was reviewed on 2026-10-27. The city pages and current DepEd dashboard reopened during implementation. Some DepEd PDFs and the SDO directory returned HTTP 403 on a later reopen, and DOH pages timed out. The already-reviewed official facts and their exact source URLs are retained; those reopen failures do not establish that a facility is closed or that a published fact is current.

## Import and maintenance

Putatan expansion currently covers the local JSON inventory, TypeScript contract, and client-side filter only. The Supabase migration still constrains `barangay` to Tunasan and Poblacion; expand that database constraint before importing this inventory. No database import was run.

Run `node --test scripts/import-pilot-places.test.mjs` to validate behavior and the committed JSON without credentials. To import, set **only** `SUPABASE_URL` and `SUPABASE_SECRET_KEY` in the local process environment, then run:

```text
node scripts/import-pilot-places.mjs --input data/pilot-places.json
```

Use a local Supabase instance with the committed migration applied. Do not put a privileged key in the JSON, browser variables, or a command argument. The script reads no environment file, and `.env.local` is already ignored by the repository's `*.local` rule. It prints counts or a generic database-stage error, never database error payloads or credentials.

Validation checks the entire file before the first database request. It rejects unsupported fields, unsupported pilot barangays/categories, duplicate keys, malformed coordinates/access/source dates, missing evidence, and OSM evidence for fields other than location. It accepts explicit nulls and unknown access values. OpenStreetMap data is credited under the [ODbL](https://www.openstreetmap.org/copyright); map display already carries OpenStreetMap attribution.

After validation, a read preflight refuses places whose verification state has advanced beyond `awaiting_review`, protecting moderated or field-checked records. Places upsert on `source_key`; source rows use deterministic UUID v5 identities based on place key, field, source type, source URL, and source name. `checkedAt` is excluded from source identity so rechecks update a source row instead of duplicating it. Place IDs remain database-owned. Import stages records as drafts, writes evidence, then publishes. A failed source or publication step leaves staged records unpublished; fix the cause and rerun the same inventory. The preflight and write stages are not one database transaction; run baseline imports while moderation is inactive.

This is a reviewed baseline importer. Reimports overwrite the imported public fields of eligible baseline keys and do not delete historical/manual sources or places omitted from the file. The importer refuses previously moderated or field-checked records; it is not an automatic freshness or removal workflow. A real local Supabase import and second-run duplicate check remain an open verification gate when the local runtime is unavailable. HTTP-boundary tests verify stable IDs and ordering, not PostgreSQL constraints or RLS.
